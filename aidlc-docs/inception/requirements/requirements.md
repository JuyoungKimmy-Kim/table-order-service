## 3. 기능 요구사항 (Functional Requirements)

### 3.1 고객용 기능 (Customer)

**FR-C1. 테이블 태블릿 자동 로그인 및 세션 관리**
- 관리자가 1회 초기 설정: 매장 식별자, 테이블 번호, 테이블 비밀번호 입력 → 로그인 정보 로컬 저장
- 1회 로그인 성공 후, 저장된 정보로 자동 로그인

**FR-C2. 메뉴 조회 및 탐색**
- 메뉴 화면이 기본 화면으로 항상 표시
- 카테고리별 분류/표시, 카테고리 간 빠른 이동
- 메뉴 상세: 메뉴명, 가격, 설명, 이미지
- UI: 카드형 레이아웃, 터치 친화 버튼(최소 44x44px), 명확한 시각 계층

**FR-C3. 장바구니 관리**
- 메뉴 추가/삭제, 수량 증감, 총 금액 실시간 계산, 장바구니 비우기
- 클라이언트 측 로컬 저장 (새로고침 시에도 유지)
- 서버 전송은 주문 확정 시에만 수행

**FR-C4. 주문 생성**
- 주문 내역 최종 확인 → 주문 확정
- 주문 성공 플로우: 주문 번호 표시 → 장바구니 자동 비우기 → 메뉴 화면 자동 리다이렉트 (5초 표시 후)
- 주문 실패 시: 에러 메시지 표시 + 장바구니 유지
- 주문 정보: 매장 식별, 테이블 식별, 메뉴 목록(메뉴명/수량/단가), 총 금액, 세션 ID

**FR-C5. 주문 내역 조회**
- 주문 시간 순 정렬, 주문별 상세(주문번호/시각/메뉴·수량/금액/상태)
- 상태: 대기중 / 준비중 / 완료
- **현재 테이블 세션의 주문만 표시** (이전 세션·이용완료 주문 제외)
- 페이지네이션 또는 무한 스크롤

### 3.2 관리자용 기능 (Admin)

**FR-A1. 매장 인증**
- 매장 식별자 + 사용자명 + 비밀번호 로그인
- 세션: 16시간 유지, JWT 토큰 기반, 새로고침 시 유지, 16시간 후 자동 로그아웃
- 보안: 비밀번호 bcrypt 해싱, 로그인 시도 제한, 세션 기반 인증

**FR-A2. 실시간 주문 모니터링**
- 주문 목록 실시간 업데이트 (**SSE**), 2초 이내 표시
- 그리드/대시보드 레이아웃: 테이블별 카드, 카드별 총 주문액, 최신 주문 n개 미리보기
- 주문 상세: 테이블번호/주문번호/주문시각/메뉴·수량(축약)/총금액
- 주문 카드 클릭 시 전체 메뉴 상세 보기
- 주문 상태 변경 (대기중/준비중/완료)
- 신규 주문 시각적 강조, 테이블별 필터링

**FR-A3. 테이블 관리 및 세션 라이프사이클**
- 테이블 태블릿 초기 설정: 테이블 번호/비밀번호 설정, 16시간 세션 생성, 자동 로그인 활성화
- 주문 삭제(직권 수정): 삭제 버튼 → 확인 팝업 → 즉시 삭제 → 총 주문액 재계산 → 성공/실패 피드백
- 테이블 세션 처리:
  - 세션 시작(첫 주문) 및 종료(이용 완료) 관리
  - 종료 시 해당 세션 주문을 과거 이력으로 이동
  - 종료 시 테이블 현재 주문 목록·총 주문액 0으로 리셋
  - 새 고객이 이전 내역 없이 시작 가능
- 과거 주문 내역 조회: 테이블별 과거 주문(시간 역순), 주문 상세, 날짜 필터, 닫기
- 데이터: OrderHistory 테이블 저장, 세션 ID 그룹화, 완료 시각 기록

**FR-A4. 메뉴 관리**
- 메뉴 조회(카테고리별), 등록(메뉴명/가격/설명/카테고리/이미지URL), 수정, 삭제, 노출 순서 조정
- 데이터 검증: 필수 필드, 가격 범위

## 4. 비기능 요구사항 (Non-Functional Requirements)

- **NFR-1 (성능/실시간)**: 관리자 대시보드에 신규 주문이 SSE를 통해 2초 이내 반영.
- **NFR-2 (인증/세션)**: 관리자 세션 16시간 JWT 기반; 테이블 세션 16시간 유지.
- **NFR-3 (보안, 기본)**: 관리자 비밀번호 bcrypt 해싱 저장; 로그인 시도 제한. (Security 확장 규칙은 미적용이나 요구사항 문서 명시 항목은 구현)
- **NFR-4 (사용성)**: 고객 UI는 터치 친화(버튼 최소 44x44px), 카드형 레이아웃, 직관적 계층.
- **NFR-5 (데이터 지속성)**: 매장/메뉴/주문/주문이력을 SQLite에 영속 저장. 장바구니는 클라이언트 로컬(브라우저) 저장.
- **NFR-6 (배포 단순성)**: 로컬 Docker Compose로 백엔드+프론트엔드+DB 일괄 기동 가능.
- **NFR-7 (데모 준비성)**: 최초 기동 시 데모용 샘플 데이터(매장/메뉴/테이블) 시딩.

## 5. 범위 제외 (Out of Scope — constraints.md)

- 실제 결제 처리, PG 연동, 영수증, 환불, 포인트/쿠폰
- 복잡한 인증(OAuth/SNS), 다단계 인증(2FA/OTP)
- 이미지 리사이징/최적화, CMS, 광고
- 알림 시스템(푸시/SMS/이메일/소리·진동)
- 주방 기능(주문 주방 전달, 식재료 재고)
- 데이터 분석/대시보드, 매출 리포트, 재고 관리, 직원 관리·권한, 예약, 리뷰, 다국어
- 외부 연동(배달 플랫폼, POS, 소셜 공유, 지도/번역 API)

## 6. 핵심 도메인 개념

- **테이블 세션**: 특정 테이블에서 고객의 첫 주문 시작부터 이용 완료 처리까지의 기간. 종료 후 다음 고객의 첫 주문 시 새 세션 시작.
- **주문 상태 흐름**: 대기중 → 준비중 → 완료
- **주문 이력(OrderHistory)**: 세션 종료 시 현재 주문이 과거 이력으로 이동, 세션 ID로 그룹화.

---

## 7. 주요 요구사항 요약

로컬 Docker Compose 기반의 MVP 테이블오더 서비스로, **고객용**(자동 로그인, 메뉴 조회, 장바구니, 주문 생성/조회)과 **관리자용**(매장 인증, SSE 실시간 모니터링, 테이블·세션 관리, 메뉴 관리)을 FastAPI + React + SQLite로 구현한다. 세션 라이프사이클(첫 주문→이용 완료→이력 이동)과 SSE 실시간성(2초 이내)이 핵심 난이도이며, 결제·알림·외부 연동은 범위에서 제외한다.
