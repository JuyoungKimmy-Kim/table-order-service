# 사용자 스토리 (User Stories)

**분해 접근법**: Persona-Based (고객 그룹 / 관리자 그룹)
**세분화**: Coarse — 기능당 1개 스토리
**Acceptance Criteria 형식**: 체크리스트/불릿
**범위**: MVP 핵심 기능 집중. 요구사항 문서의 "선택사항"은 각 스토리 내 **[Optional]** 로 명시.
**INVEST**: 각 스토리는 Independent, Negotiable, Valuable, Estimable, Small, Testable 하도록 작성.

> 참고: 우선순위/크기 표기는 사용자 결정(Q6=C)에 따라 생략합니다.

---

## 그룹 A: 매장 고객 (P-CUSTOMER)

### US-C1. 테이블 태블릿 자동 로그인 및 세션 관리
**As a** 매장 고객,
**I want** 별도의 로그인 절차 없이 테이블 태블릿으로 즉시 주문 화면에 진입하기를,
**So that** 대기나 번거로움 없이 바로 주문을 시작할 수 있다.

**Acceptance Criteria**
- [ ] 관리자가 최초 1회 매장 식별자, 테이블 번호, 테이블 비밀번호로 로그인하면 해당 정보가 로컬(브라우저)에 저장된다.
- [ ] 이후 태블릿을 다시 열면 저장된 정보로 자동 로그인되어 별도 입력 없이 메뉴 화면이 표시된다.
- [ ] 저장된 세션이 유효하지 않으면(만료/삭제) 초기 설정 화면으로 되돌아간다.
- [ ] 고객에게는 로그인 절차가 노출되지 않는다.

---

### US-C2. 메뉴 조회 및 탐색
**As a** 매장 고객,
**I want** 카테고리별로 정리된 메뉴를 상세 정보와 함께 탐색하기를,
**So that** 원하는 메뉴를 쉽고 빠르게 찾아 선택할 수 있다.

**Acceptance Criteria**
- [ ] 앱 진입 시 메뉴 화면이 기본 화면으로 항상 표시된다.
- [ ] 메뉴가 카테고리별로 분류되어 표시되고, 카테고리 간 빠르게 이동할 수 있다.
- [ ] 각 메뉴는 메뉴명, 가격, 설명, 이미지를 표시한다.
- [ ] 메뉴는 카드 형태 레이아웃으로 표시된다.
- [ ] 터치 대상 버튼은 최소 44x44px 이상이다.

---

### US-C3. 장바구니 관리
**As a** 매장 고객,
**I want** 선택한 메뉴를 장바구니에 담고 수량을 조정하며 총액을 확인하기를,
**So that** 주문을 확정하기 전에 구성을 자유롭게 검토·수정할 수 있다.

**Acceptance Criteria**
- [ ] 메뉴를 장바구니에 추가/삭제할 수 있다.
- [ ] 장바구니 항목의 수량을 증가/감소할 수 있다.
- [ ] 총 금액이 항목/수량 변경에 따라 실시간으로 재계산된다.
- [ ] 장바구니 전체 비우기가 가능하다.
- [ ] 장바구니는 클라이언트(브라우저)에 저장되어 페이지 새로고침 후에도 유지된다.
- [ ] 장바구니 내용은 주문 확정 시에만 서버로 전송된다.

---

### US-C4. 주문 생성
**As a** 매장 고객,
**I want** 장바구니 내용을 최종 확인 후 주문으로 확정하기를,
**So that** 선택한 메뉴가 매장에 정상 접수된다.

**Acceptance Criteria**
- [ ] 주문 확정 전 주문 내역(메뉴명/수량/단가/총액)을 최종 확인할 수 있다.
- [ ] 주문 확정 시 주문 정보에 매장 식별, 테이블 식별, 메뉴 목록, 총 금액, 세션 ID가 포함된다.
- [ ] 주문 성공 시 주문 번호가 표시된다.
- [ ] 주문 성공 시 장바구니가 자동으로 비워진다.
- [ ] 주문 성공 화면이 표시된 후 메뉴 화면으로 자동 리다이렉트된다(요구사항상 약 5초 표시 후).
- [ ] 주문 실패 시 에러 메시지가 표시되고 장바구니 내용은 유지된다.

---

### US-C5. 주문 내역 조회 (현재 세션)
**As a** 매장 고객,
**I want** 현재 테이블 세션에서 접수된 주문 이력과 상태를 확인하기를,
**So that** 내 주문이 잘 접수되었는지, 진행 상태가 어떤지 알 수 있다.

**Acceptance Criteria**
- [ ] 주문 목록이 주문 시각 순으로 정렬되어 표시된다.
- [ ] 각 주문은 주문 번호, 주문 시각, 메뉴 및 수량, 주문 금액, 주문 상태(대기중/준비중/완료)를 표시한다.
- [ ] **현재 테이블 세션의 주문만** 표시되며, 이전 세션 및 이용 완료 처리된 주문은 제외된다.
- [ ] 주문이 많을 경우 페이지네이션 또는 무한 스크롤로 탐색할 수 있다.
- [ ] **[Optional]** 주문 상태가 실시간으로 업데이트된다. (요구사항 문서상 선택사항)

## 그룹 B: 매장 관리자 (P-ADMIN)

### US-A1. 매장 인증 및 세션 유지
**As a** 매장 관리자,
**I want** 매장 계정으로 안전하게 로그인하고 장시간 세션을 유지하기를,
**So that** 근무 중 반복 로그인 없이 관리 작업을 지속할 수 있다.

**Acceptance Criteria**
- [ ] 매장 식별자, 사용자명, 비밀번호로 로그인할 수 있다.
- [ ] 로그인 성공 시 JWT 토큰 기반 세션이 16시간 동안 유지된다.
- [ ] 브라우저 새로고침 후에도 세션이 유지된다.
- [ ] 16시간 경과 시 자동 로그아웃된다.
- [ ] 비밀번호는 bcrypt로 해싱되어 저장된다.
- [ ] 로그인 시도 횟수 제한이 적용된다.

---

### US-A2. 실시간 주문 모니터링 (SSE)
**As a** 매장 관리자,
**I want** 들어오는 주문을 테이블별 대시보드에서 실시간으로 확인하기를,
**So that** 신규 주문을 놓치지 않고 신속히 처리할 수 있다.

**Acceptance Criteria**
- [ ] 주문 목록이 Server-Sent Events(SSE)를 통해 실시간으로 업데이트된다.
- [ ] 신규 주문이 발생 후 2초 이내에 대시보드에 표시된다.
- [ ] 대시보드는 그리드 레이아웃으로 테이블별 카드를 표시한다.
- [ ] 각 테이블 카드에 총 주문액과 최신 주문 n개 미리보기가 표시된다.
- [ ] 각 주문은 테이블 번호, 주문 번호, 주문 시각, 메뉴 및 수량(축약), 총 금액을 표시한다.
- [ ] 주문 카드를 클릭하면 전체 메뉴 목록 상세를 볼 수 있다.
- [ ] 신규 주문은 색상 변경/애니메이션 등으로 시각적으로 강조된다.
- [ ] 테이블별 필터링이 가능하다.

---

### US-A3. 주문 상태 변경
**As a** 매장 관리자,
**I want** 각 주문의 진행 상태를 변경하기를,
**So that** 조리/서빙 진행 상황을 반영하고 고객에게도 상태가 전달된다.

**Acceptance Criteria**
- [ ] 주문 상태를 대기중 → 준비중 → 완료로 변경할 수 있다.
- [ ] 상태 변경 결과가 저장되고, 관련 화면(고객/관리자)에 반영된다.

---

### US-A4. 주문 삭제 (직권 수정)
**As a** 매장 관리자,
**I want** 잘못 접수된 특정 주문을 삭제하기를,
**So that** 오주문을 정정하고 테이블 총액을 정확히 유지할 수 있다.

**Acceptance Criteria**
- [ ] 특정 주문에 대한 삭제 버튼이 제공된다.
- [ ] 삭제 전 확인 팝업이 표시된다.
- [ ] 확인 시 해당 주문이 즉시 삭제된다.
- [ ] 삭제 후 해당 테이블의 총 주문액이 재계산된다.
- [ ] 성공/실패 피드백이 표시된다.

---

### US-A5. 테이블 세션 라이프사이클 관리
**As a** 매장 관리자,
**I want** 테이블 세션의 시작과 종료(이용 완료)를 관리하기를,
**So that** 새 손님이 이전 주문 내역 없이 깨끗한 상태에서 시작할 수 있다.

**Acceptance Criteria**
- [ ] 테이블 세션은 해당 테이블의 첫 주문 시 시작된다.
- [ ] 관리자가 테이블 이용 완료(세션 종료)를 처리할 수 있으며, 처리 전 확인 팝업이 표시된다.
- [ ] 세션 종료 시 해당 세션의 주문 내역이 과거 이력(OrderHistory)으로 이동한다.
- [ ] 세션 종료 시 테이블의 현재 주문 목록과 총 주문액이 0으로 리셋된다.
- [ ] 세션 종료 후 새 고객이 이전 내역 없이 주문을 시작할 수 있다.
- [ ] 과거 이력은 세션 ID로 그룹화되고 완료 시각이 기록된다.
- [ ] 성공/실패 피드백이 표시된다.

---

### US-A6. 과거 주문 내역 조회
**As a** 매장 관리자,
**I want** 테이블별 과거(이용 완료된) 주문 내역을 조회하기를,
**So that** 지난 이용 기록을 확인하고 필요 시 참고할 수 있다.

**Acceptance Criteria**
- [ ] "과거 내역" 진입점(버튼)이 제공된다.
- [ ] 테이블별 과거 주문 목록이 시간 역순으로 표시된다.
- [ ] 각 주문은 주문 번호, 시각, 메뉴 목록, 총 금액, 매장 이용 완료 시각을 표시한다.
- [ ] 날짜 기준 필터링이 가능하다.
- [ ] "닫기"로 대시보드로 복귀할 수 있다.

---

### US-A7. 메뉴 관리
**As a** 매장 관리자,
**I want** 메뉴 정보를 등록·수정·삭제하고 노출 순서를 조정하기를,
**So that** 매장 메뉴를 동적으로 최신 상태로 유지할 수 있다.

**Acceptance Criteria**
- [ ] 메뉴를 카테고리별로 조회할 수 있다.
- [ ] 메뉴를 등록할 수 있다(메뉴명, 가격, 설명, 카테고리, 이미지 URL).
- [ ] 메뉴를 수정·삭제할 수 있다.
- [ ] 메뉴 노출 순서를 조정할 수 있다.
- [ ] 등록/수정 시 필수 필드와 가격 범위가 검증된다.
